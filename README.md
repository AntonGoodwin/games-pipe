# game-pipe — фабрика игр без человека

Пайплайн сам создаёт игры по короткому описанию: спецификация → приёмочные тесты (до кода) → реализация → проверки → ревью → документация → ретроспектива. Этапами управляет детерминированный оркестратор, AI работает внутри этапов. Код игр и платформы руками не пишется и не правится.

## Команды

Из Claude Code Desktop (slash-команды) или из терминала — это одно и то же:

| Что | Desktop | Терминал |
|---|---|---|
| Создать платформу (один раз) | `/platform-build` | `node factory/run.ts platform` |
| Создать игру | `/game-new specs/coin.md` | `node factory/run.ts new specs/coin.md` |
| Доработать по замечаниям | `/game-feedback mines feedback/mines-01.md` | `node factory/run.ts feedback mines feedback/mines-01.md` |
| Изменить решение пайплайна | `/game-decide mines D-002 "5 мин"` | `node factory/run.ts decide mines D-002 "5 мин"` |
| Один этап вручную | `/game-stage GAME-001 review` | `node factory/run.ts stage GAME-001 review` |
| Продолжить задачу | `/game-resume GAME-001` | `node factory/run.ts resume GAME-001` |
| Список игр (id для feedback/decide) | `/game-list` | `node factory/run.ts games` |
| Статус и метрики | `/game-status` | `node factory/run.ts status` · `summary` |
| Запустить приложение | `/app-start` | `pnpm start` → http://localhost:4000 |

Подготовка: Node 24, `pnpm install`, залогиненный Claude Code (агенты запускаются как `claude -p` по подписке).

## Как устроено

```
команда ─► оркестратор (factory/run.ts + factory/pipeline.yaml) ─► этапы
              │ читает только факты: коды возврата, хэши, поле outcome по JSON-схеме
              ├─ AI-этап: claude -p --agent <роль> --json-schema … (агенты в .claude/agents/)
              └─ check-этап: tsc, vitest, хэши, границы, ссылки — без AI
```

Конвейер новой игры:

```
scaffold → spec → tests → red_check → lock_tests → implement ⇄ verify → review → docs → docs_check → learn
                    ▲                        │ dispute
                    └── accepted ─ dispute ◄─┘   rejected → решение «прав тест» в журнал, работа идёт дальше
```

- **Тесты пишет отдельный агент до реализации** по Gherkin-сценариям; `red_check` требует, чтобы на заглушке они падали, и чтобы каждый сценарий SC-N был покрыт.
- **Исполнитель не может изменить тесты — технически**, тремя слоями: хук PreToolUse блокирует запись вне разрешённых этапу путей; после этапа оркестратор откатывает любые изменения вне разрешённых путей; перед прогоном тесты сверяются по sha256 с заблокированной копией (`.factory/locked/`) и восстанавливаются из неё.
- **Спор «тест против кода»:** разработчик возвращает `dispute`, агент тестирования либо правит тест сам, либо отклоняет. Отклонённый спор не блокирует работу: оркестратор записывает решение «прав тест» в журнал, человек может изменить его позже через `/game-decide`.
- **Платформа** создаётся пайплайном один раз и замораживается (`.factory/platform.lock.json`); в игровых запусках любые её изменения откатываются и валят проверку.
- **Лимиты попыток** — в `factory/pipeline.yaml`; при исчерпании запуск завершается с понятной причиной в `report.md`.
- **Обучение:** после каждого запуска (в том числе неудачного) агент `librarian` разбирает события, оркестратор пишет записи в `kb/`. Следующие этапы получают записи своей роли и отмечают применённые — это видно в отчёте. Дифф базы — `runs/<id>/kb-diff.patch`, история — `git log kb/`.
- **Метрики:** по каждому этапу итерации, время, токены (из `claude -p --output-format stream-json`) — `runs/<id>/metrics.json`, `report.md`, сводка `runs/summary.md`.

## Где что лежит

| Путь | Кто пишет | Что |
|---|---|---|
| `factory/`, `.claude/`, `docs/conventions.md` | человек | оркестратор, агенты, конвенции |
| `specs/`, `feedback/` | человек | входные описания игр и замечаний |
| `platform/` | пайплайн, один раз | кошелёк, лимиты, раунды, SDK, testkit |
| `games/<id>/` | пайплайн | спека, тесты, код, интерфейс, README |
| `local-jira/` | оркестратор | задачи (по одной на игру, доработку, решение) |
| `decisions/` | оркестратор | журнал решений и решения человека |
| `kb/` | оркестратор (по ретроспективе) | база знаний |
| `runs/` | оркестратор | логи этапов, отчёты, метрики |
