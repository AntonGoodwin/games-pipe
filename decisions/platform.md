# Журнал решений: platform

Допущения, которые пайплайн принял сам, и решения человека поверх них.
Файл ведёт оркестратор; человек меняет решения командой `/game-decide`.

## D-001 Как округлять деньги до центов?

- Статус: допущение
- Допущение: Math.round(x*100)/100 для ставок и выплат; ставка округляется до проверки лимитов
- Обоснование: Простое детерминированное правило, одинаковое для ядра и testkit
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-002 В каком порядке проверяется запрос на открытие раунда?

- Статус: допущение
- Допущение: Игра → лимиты → validateParams → открытый раунд → списание в кошельке → start
- Обоснование: Все проверки без участия денег идут раньше обращения к кошельку, как требует описание для лимитов
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-003 Какие HTTP-статусы у кодов ошибок?

- Статус: допущение
- Допущение: 400 BET_OUT_OF_LIMITS/INVALID_PARAMS/INVALID_ACTION, 402 INSUFFICIENT_FUNDS, 404 GAME_NOT_FOUND/ROUND_NOT_FOUND, 409 ROUND_ALREADY_OPEN/ROUND_CLOSED
- Обоснование: Стандартная семантика HTTP; 402 совпадает с кошельком
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-004 Что делать со ставкой, которая не является числом?

- Статус: допущение
- Допущение: BET_OUT_OF_LIMITS
- Обоснование: INVALID_PARAMS относится к параметрам игры, а не к ставке
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-005 Что если игра вернула отрицательную или не конечную выплату?

- Статус: допущение
- Допущение: 500 INTERNAL_ERROR, выплата не делается, раунд остаётся открытым в прежнем состоянии
- Обоснование: Защищает деньги от ошибки в игре
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-006 Что если кошелёк недоступен?

- Статус: допущение
- Допущение: 502 WALLET_UNAVAILABLE; при списании раунд не создаётся; при выплате раунд ждёт выплаты, и она повторяется с тем же txId при следующем open
- Обоснование: Идемпотентность txId позволяет безопасно повторить выплату
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-007 Повтор txId после отказа 402 и валидация amount в кошельке?

- Статус: допущение
- Допущение: Отказ 402 записывается в журнал, повтор возвращает тот же ответ; amount должен быть конечным, для bet > 0, для payout ≥ 0, иначе 400 INVALID_AMOUNT
- Обоснование: Описание требует «тот же ответ» при повторе; некорректные суммы нельзя проводить
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-008 Ограничение на открытые раунды — для каждой игры или для игрока в целом?

- Статус: допущение
- Допущение: Один открытый раунд на каждую игру, раунды разных игр независимы
- Обоснование: В описании сказано «в игре»
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-012 Как ведёт себя SDK, если action вызван без раунда?

- Статус: допущение
- Допущение: SDK запоминает roundId из open/startRound; без раунда action отклоняется с {code: ROUND_NOT_FOUND} без запроса к серверу
- Обоснование: В action(action) нет roundId, значит, клиент должен его хранить
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]

## D-013 Детали testkit (rng по умолчанию, формат transactions, fixedRng на краях)?

- Статус: допущение
- Допущение: По умолчанию seededRng(1), startBalance 100; transactions: {txId, type, roundId, amount, balanceAfter} без отклонённых операций; fixedRng бросает ошибку, когда значения кончились, и отклоняет значения вне [0, 1)
- Обоснование: Детерминизм и громкий отказ на ошибке в тесте
- Источник: [[local-jira/PLAT-001-platform-platform|PLAT-001]] · этап spec · [[runs/r-001-PLAT-001/report|r-001-PLAT-001]]
