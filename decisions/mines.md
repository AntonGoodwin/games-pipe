# Журнал решений: mines

Допущения, которые пайплайн принял сам, и решения человека поверх них.
Файл ведёт оркестратор; человек меняет решения командой `/game-decide`.

## D-001 Сколько мин на поле и выбирает ли их число игрок?

- Статус: допущение
- Допущение: Ровно 3 мины, игрок число не выбирает; params = {}
- Обоснование: В описании число мин не задано. Фиксированное значение упрощает правила, валидацию и тесты; 3 из 25 — типичное значение для Mines
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

- Обоснование: Простой однозначный адрес клетки для action, тестов и интерфейса
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-003 Как rng превращается в расположение мин и когда расставляются мины?

- Статус: допущение
- Допущение: В start, 3 вызова rng: частичная тасовка Фишера — Йетса, j = i + floor(rᵢ × (25 − i)), мины — c[0..2]; action rng не использует
- Обоснование: Исход фиксируется до первого хода (честность, без подстройки под ходы игрока). Ровно 3 вызова дают детерминированное управление через fixedRng. После rng ничего не может упасть
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-004 Как считается множитель и какой house edge?

- Статус: допущение
- Допущение: M(k) = round2(0.98 × C(25,k)/C(22,k)), M(0) = 1 только для отображения; выплата = bet × M(k)
- Обоснование: Честный множитель для 3 мин с тем же 2 % house edge, что в «Монетке». Округление множителя до центов даёт однозначные числа на экране и в тестах
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-005 Можно ли забрать выигрыш до первой открытой клетки?

- Статус: допущение
- Допущение: Нет: cashout при k = 0 даёт INVALID_ACTION
- Обоснование: Иначе выплата была бы bet × 1 без риска или требовала отдельного правила; описание говорит о выигрыше, который появляется после безопасных клеток
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-006 Что происходит, когда открыты все безопасные клетки?

- Статус: допущение
- Допущение: Раунд завершается сам с выплатой bet × M(22) = bet × 2254, outcome = cleared
- Обоснование: Больше ходить некуда; оставлять раунд открытым без возможных ходов, кроме cashout, бессмысленно
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-007 Формат action

- Статус: допущение
- Допущение: Объект { type: 'reveal', cell } или { type: 'cashout' }; всё остальное, а также уже открытая клетка, даёт INVALID_ACTION без изменения состояния
- Обоснование: Платформа передаёт action как произвольный JSON. Объект однозначнее строк, а строгая проверка исключает двусмысленность
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-008 Как валидировать params?

- Статус: допущение
- Допущение: Принимается объект или undefined, лишние поля (включая mines) отбрасываются, результат {}; null, массив, строка и число дают INVALID_PARAMS
- Обоснование: Параметров у игры нет. testkit и SDK могут не передать params; явный мусор отклоняется так же, как в «Монетке»
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-009 Что показывает publicView?

- Статус: допущение
- Допущение: Пока раунд открыт: { mineCount, revealed, multiplier, nextMultiplier }; после завершения дополнительно mines, hit, outcome, а nextMultiplier = null
- Обоснование: До конца раунда мины не раскрываются (конвенции). nextMultiplier помогает игроку решить, забирать ли выигрыш
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-010 Как устроен интерфейс?

- Статус: допущение
- Допущение: data-testid: balance, bet-input, play, cashout, multiplier, next-multiplier, payout, error, cell-0…cell-24 с data-cell-state hidden|safe|mine; data-state idle|playing|won|lost; открытый раунд восстанавливается из open().activeRound
- Обоснование: Следует конвенциям по data-testid/data-state; для многоходовой игры playing означает открытый раунд
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап spec · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-011 Какой полный view проверять там, где сценарий перечисляет только часть полей (SC-3, SC-4, SC-5, SC-9)?

- Статус: допущение
- Допущение: Проверяется полный объект по правилам publicView из спеки, например в SC-3 multiplier = M(0) = 1, nextMultiplier = null, mines = [7, 12, 19]
- Обоснование: Эти значения однозначно следуют из раздела «Что видит игрок». Точное сравнение ловит раскрытие мин и неверный множитель
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап tests · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-012 Добавлять ли проверки сверх буквы сценариев?

- Статус: допущение
- Допущение: Да, в рамках тех же SC-N: M(1)…M(5) и cashout при k = 5 (1.98), cashout при k = 21 со ставкой 2 (1127, баланс 1225), каждая из трёх мин проигрывает, соседние клетки безопасны, после cashout повторный ход даёт ROUND_CLOSED, мина и cleared на уровне модуля
- Обоснование: Все числа выводятся из формулы и таблицы спеки. Это нужно, чтобы тесты ловили ошибки в коэффициенте, сдвиг k на единицу и повторную выплату
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап tests · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-014 Как в happy-dom проверять повторную загрузку страницы без влияния скрипта прошлой загрузки?

## D-015 Почему тесты не прогнаны на эталонной реализации?

- Статус: допущение
- Допущение: Прогон на заглушке выполнен: 30 падений, 1 проход (SC-11). Создать эталонную реализацию в scratchpad не дал Bash в режиме don't ask. Тесты сверены вручную с текстом сценариев, формулой M(k), тасовкой Фишера — Йетса, контрактом testkit и engine. Итоговая проверка остаётся за red_check и verify
- Обоснование: По KB-007 запрет на запуск не обходится
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап tests · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-016 Что показывает интерфейс, когда ход отклонён ошибкой платформы (например, ROUND_CLOSED)?

- Статус: допущение
- Допущение: Раунд остаётся в прежнем виде: data-state, клетки и баланс не меняются, в error показываются код и короткое пояснение. Состояние заново через open() не запрашивается.
- Обоснование: В спецификации и D-013 сказано только о показе кода ошибки. Повторный запрос состояния — поведение, которого в спецификации нет.
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап implement · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-017 Можно ли менять ставку во время открытого раунда?

- Статус: допущение
- Допущение: Нет: в состоянии playing поле bet-input заблокировано вместе с play.
- Обоснование: Ставка раунда уже списана, новую можно сделать только после его завершения. Спецификация блокирует play в playing, и поле ставки блокируется вслед за ней.
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап implement · [[runs/r-006-GAME-002/report|r-006-GAME-002]]

## D-018 Как показывать множитель, когда следующего нет (раунд завершён или ещё не начат)?

- Статус: допущение
- Допущение: multiplier показывает «×M(k)» из view, next-multiplier показывает «×M(k+1)» или «—», если nextMultiplier = null. Без раунда в обоих полях «—».
- Обоснование: Значения берутся из publicView, а для отсутствующего значения используется понятный прочерк.
- Источник: [[local-jira/GAME-002-mines-new-game|GAME-002]] · этап implement · [[runs/r-006-GAME-002/report|r-006-GAME-002]]
