# implement: done

Исправил все 4 замечания ревью. Тесты платформы проходят (46 из 46), `tsc --noEmit` без ошибок. Новое поведение отдельным скриптом проверить не удалось: хук этапа не даёт писать вне platform/**. Поэтому оно проверено только чтением кода, отдельных тестов на него нет.

R-1. Игра больше не получает сам генератор платформы. На каждый вызов start или action движок создаёт новую замороженную обёртку `guardedRng`. Обёртка считает обращения и превращает число вне [0, 1) в INTERNAL_ERROR. Объект cryptoRng заморожен. Ссылка на crypto.randomBytes берётся при загрузке ядра, до подключения игр.

R-2. Если игра упала после первого rng.next() (исключение, некорректный шаг или состояние, которое не сериализуется в JSON), раунд помечается `broken`. Он остаётся открытым для ручного разбора: ставка не возвращается, ходы отклоняются с INTERNAL_ERROR, view = null, новый раунд даёт ROUND_ALREADY_OPEN. Если ошибка случилась до обращения к rng, всё работает как раньше: ход можно повторить, а падение в start аннулирует раунд с возвратом ставки (D-022). Порядок «сначала проверка хода, потом rng, после rng никаких исключений» записан в контракт sdk/types.ts.

R-3. wallet.json и rounds.json пишутся через новую функцию `shared/fs.ts` `writeFileDurable`: временный файл, fsync, rename, fsync каталога.

R-4. Кошелёк запускается отдельным процессом: `platform/wallet/main.ts` через child_process.fork. Токен передаётся по IPC. В wallet-client ссылка на http.request берётся до загрузки игр. В контракт types.ts добавлен запрет для серверного модуля игры на process, globalThis, require, import(), fetch, eval/Function и node:*. Сама проверка этого запрета живёт в коде фабрики и на этом этапе мне недоступна.
