# review: fail

### reviewer-integrity: НЕ пройдено (4 замечаний)
- R-1 [blocking] platform/core/engine.ts:172 — Игра получает в ctx.rng сам генератор платформы (this.#rng), общий для всех игр процесса. В ядре это экспортируемый изменяемый объект cryptoRng (platform/core/index.ts:55). Любой модуль игры может без единого импорта выполнить `ctx.rng.next = () => 0.99` (или обернуть next с кэшем) и подменить исход всех следующих раундов во всех играх, в том числе чужих. Проверка границ по импортам этого не заметит. Платформу после этого этапа заморозят, поэтому защищаться нужно сейчас. То же место в action: engine.ts:207. Как исправить: на каждый вызов start/action передавать новую замороженную обёртку, например `Object.freeze({ next: () => { const v = this.#rng.next(); if (!(v >= 0 && v < 1)) throw internal('rng вне [0,1)'); return v; } })`, а сам cryptoRng тоже заморозить через Object.freeze. Тест: игра на старте присваивает ctx.rng.next, а исход следующего раунда другой игры от этого не меняется.
- R-2 [minor] platform/core/engine.ts:210 — Повторный бросок через ошибку игры. Если action уже взял число из rng, а потом бросил исключение (INVALID_ACTION или любое другое), вернул некорректный шаг или несериализуемое состояние, раунд остаётся прежним. Игрок повторяет тот же ход и получает новое случайное число. На старте ещё хуже: исключение в start аннулирует раунд с возвратом ставки (строки 175–178, D-022). Тогда игра с ошибкой только в проигрышной ветке даёт бесплатные перебросы до выигрыша. Как исправить: (1) записать в контракт sdk/types.ts, что игра обязана проверить action/params до первого обращения к rng и не бросать исключений после него; (2) в движке помечать раунд как сломанный (для ручного разбора, без автоповтора), если action упал на INTERNAL_ERROR после вызова rng.next(). Обращения можно считать в обёртке из предыдущего замечания.
- R-3 [minor] platform/wallet/index.ts:71 — wallet.json (а также rounds.json в core/store.ts:70) записывается через writeFileSync и rename без fsync. При сбое питания или ОС rename может сохраниться раньше данных, и тогда в файле окажется пустой или старый баланс. Для rounds.json есть отдельный риск: запись pendingBet до списания перестаёт гарантировать сохранность ставки. Как исправить: открыть tmp-файл, записать, вызвать fs.fsyncSync(fd) и close, затем renameSync, затем fsync каталога.
- R-4 [minor] platform/core/games.ts:49 — Серверный модуль игры загружается в процесс ядра и кошелька (start.ts поднимает оба в одном процессе). Без статических импортов игре доступны process.getBuiltinModule('node:http' | 'node:fs' | 'node:crypto'), globalThis.fetch и динамический import(). Через них можно подменить http.request и перехватить x-wallet-token или суммы выплат, подменить crypto.randomBytes под cryptoRng или переписать data/*.json. Изоляцию денег, которую предполагает контракт, это обходит. Полностью закрыть дыру внутри одного процесса нельзя. Как исправить: зафиксировать в правилах проверки границ игр запрет на process, globalThis, import(), require, fetch и eval в games/*/server. Лучше запускать кошелёк отдельным процессом (child_process), чтобы токен и баланс не лежали в памяти процесса с кодом игр.
