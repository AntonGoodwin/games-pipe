# review: fail

### reviewer-integrity: НЕ пройдено (3 замечаний)
- R-1 [blocking] platform/wallet/index.ts:105 — Кошелёк никак не ограничивает, кто его вызывает. POST /bet и /payout разбирают тело как JSON при любом Content-Type (readJson не смотрит заголовок), а Origin не проверяется. Отсюда два пути атаки. (1) CSRF из браузера: любой сайт, который открыл игрок, отправляет «простой» запрос `fetch('http://127.0.0.1:4001/payout', {method:'POST', body:'{"txId":"x","roundId":"y","amount":1000000}'})` без preflight (text/plain) и зачисляет произвольную сумму, а через /bet списывает баланс. (2) Обход изоляции денег: серверный модуль игры работает в процессе ядра и может вызвать глобальный fetch на 4001 без единого импорта, поэтому проверка границ по импортам этого не поймает. Для ядра такая защита уже сделана (D-039), для кошелька, который реально двигает деньги, нет. Как исправить: в кошельке так же, как в checkSameOrigin, отклонять запросы с заголовком Origin (403) и POST с телом не application/json (415). Кроме того, пусть start.ts генерирует общий секрет (crypto.randomUUID) и передаёт его в startWallet({ token }) и startCore({ walletToken }); wallet-client шлёт его в заголовке, а кошелёк без верного токена отвечает 401. Если token не передан, кошелёк работает как сейчас, и тесты (helpers.ts шлёт application/json без Origin) не ломаются.
- R-2 [minor] platform/core/index.ts:150 — checkSameOrigin сравнивает Origin с заголовком Host, но сам Host не проверяет. При DNS rebinding (evil.example резолвится в 127.0.0.1) браузер отправит Origin http://evil.example:4000 и Host evil.example:4000. Они совпадут, и сторонняя страница сможет делать ставки и ходы от имени игрока. Как исправить: принимать POST /api/* только при Host из белого списка: localhost:<port>, 127.0.0.1:<port>, [::1]:<port> (фактический порт сервера). То же стоит применить к кошельку.
- R-3 [minor] platform/core/engine.ts:463 — Если кошелёк отклонил отложенную выплату окончательно (4xx, wallet-client переводит это в INTERNAL_ERROR), раунд навсегда остаётся с pendingPayout. #recover бросает ошибку на каждом open() и startRound() этой игры, поэтому игра полностью блокируется. Игрок не видит ни activeRound, ни баланса через open, и выхода из этого состояния нет. Как исправить: при окончательном отказе на выплате (не isUncertain) логировать и возвращать из open() хотя бы лимиты, баланс и activeRound с view = null, а не ронять весь ответ. Либо пометить раунд для ручного разбора и не блокировать им open.
