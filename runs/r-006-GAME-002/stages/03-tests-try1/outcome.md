# tests: done

Написал приёмочные тесты «Мин» в games/mines/tests/, по три файла на группы сценариев. В rounds.test.ts SC-1…SC-13 идут через createTestPlatform с fixedRng. Проверяются точные выплаты и балансы, журнал транзакций [type, amount, balanceAfter], то, что view открытого раунда не раскрывает мины, коды INVALID_ACTION, INVALID_PARAMS, ROUND_CLOSED, ROUND_ALREADY_OPEN, BET_OUT_OF_LIMITS и INSUFFICIENT_FUNDS, а также то, что rng не расходуется при отказе. В module.test.ts SC-14 проверяет контракт GameModule: start вызывает rng ровно 3 раза, мины расставлены по всем трём строкам таблицы, action не обращается к rng, переданный state не меняется, состояние сериализуется, проверены выплаты при cashout, мине и cleared. В ui.test.ts SC-15 проверяет интерфейс в happy-dom с подменённым window.PlatformSDK: переходы idle → playing → won, блокировку клеток и cashout, раскрытие мин, восстановление раунда из activeRound и показ кода ROUND_CLOSED. Тесты дополнительно ловят типичные ошибки: множитель на одну клетку больше (таблица M(1)…M(5), M(21) и M(22)), выплату при проигрыше, раннее автозавершение до 22-й клетки, приведение строки "7" к числу и мину по индексу j до обмена. На заглушке прогон дал 30 падений и 1 проход. Прошёл SC-11 (отказ по лимитам), его делает платформа. После прогона я ещё переименовал один тест (сама проверка не изменилась). Таблицу M(k) и расстановку мин в спеке пересчитал вручную, расхождений нет. Сверить тесты с эталонной реализацией не смог: Bash для этого был запрещён.
