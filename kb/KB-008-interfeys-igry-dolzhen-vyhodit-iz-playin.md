# Интерфейс игры: закрытый список кодов «только показать», после всех остальных ошибок — пересинхронизация через sdk.open()

**Проблема.** В GAME-002 интерфейс Мин оставался в состоянии playing после ROUND_CLOSED и WALLET_UNAVAILABLE (R-1). Правило KB-008 предлагало перечислять коды для пересинхронизации, включая WALLET_UNAVAILABLE. В GAME-003 этот литерал в games/mines/ui/index.html провалил verify: проверка границ ищет подстроку «wallet». Developer перевернул логику, и спецификация (D-028) разошлась с кодом (R-1, D-042).

**Причина.** В спецификации пересинхронизация задавалась списком кодов, где есть слово WALLET. Проверка границ (factory/lib/checks.ts, boundaryViolations, /wallet|:4001/i) запрещает эту подстроку в любом файле игры. Кроме того, при списке «на что пересинхронизироваться» неизвестные и новые коды платформы оставляют интерфейс в устаревшем состоянии.

**Правило.** Analyst: в разделе интерфейса любой игры задай закрытый список кодов, которые только показываются и не меняют состояние: BET_OUT_OF_LIMITS, INSUFFICIENT_FUNDS, INVALID_PARAMS, INVALID_ACTION, NETWORK_ERROR. На любой другой код, в том числе ROUND_CLOSED, ROUND_NOT_FOUND, ошибку недоступности кошелька, INTERNAL_ERROR и неизвестные коды, интерфейс показывает сообщение и заново вызывает sdk.open(). Если activeRound есть, примени его, иначе перейди в idle. Добавь на это сценарий с подменённым SDK. Код ошибки кошелька не перечисляй литералом ни в спецификации для UI, ни в коде игры: для него работает ветка «остальные коды». Developer: реализуй это одной функцией пересинхронизации без перезагрузки страницы. Текст ошибки для кодов вне списка бери общий или из message, который вернула платформа. Reviewer-rules: если спецификация этого не задаёт, отмечай это как minor со ссылкой на это правило и не открывай вопрос заново. Логику «остальные коды → open()» нарушением не считай.
