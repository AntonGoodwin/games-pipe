# Монетка
Спецификация: [[games/coin/spec]] · Решения: [[decisions/coin]] · Платформа: [[platform/spec]] · Задача: [[local-jira/GAME-001-coin-new-game]]

Игрок выбирает сторону монеты и делает ставку. Если угадал, получает выплату ×1.96.

## Устройство
- `manifest.json` — `{ id: "coin", title, server, ui }`, по нему платформа находит модуль и страницу.
- `server/index.ts` — `export default` объект `GameModule`: проверка параметров, бросок, выплата, публичное представление. Из платформы импортирует только `platform/sdk/types.ts` (`GameModule`, `Rng`, `Step`, `GameError`). Экспортирует также типы `Side`, `CoinParams`, `CoinState` и константу `PAYOUT_MULTIPLIER = 1.96`.
- `ui/index.html` — интерфейс: один файл с инлайновыми стилями и скриптом, работает только через `window.PlatformSDK` (`/sdk.js`).
- `tests/` — приёмочные тесты: `rounds.test.ts` (через платформу, SC-1…SC-9), `module.test.ts` (контракт модуля, SC-10), `ui.test.ts` (интерфейс в happy-dom, SC-11).

Кошелёк, лимиты ставки (1…10), списание, зачисление и округление до центов делает платформа. Игра только возвращает `payout` в `Step`.

## Состояние раунда
- Параметры: `{ side: "heads" | "tails" }`. Принимаются строго эти строки, лишние поля отбрасываются ([[decisions/coin#D-005]]).
- `state = { side, outcome, win }` — выбранная сторона, выпавшая сторона и признак выигрыша. Обычный JSON-объект.
- Раунд состоит из одного шага ([[decisions/coin#D-003]]). `start` сразу возвращает `status: "finished"`, и платформа закрывает раунд в том же запросе. Открытых раундов не бывает: после обновления страницы `open("coin").activeRound` = `null`.
- `action` всегда бросает `GameError('INVALID_ACTION')` и не трогает rng. Через платформу такой вызов до игры не доходит, потому что платформа раньше отвечает `ROUND_CLOSED`.

## Как определяется результат
1. `start` повторно вызывает `validateParams` ([[decisions/coin#D-013]]). Всё, что может бросить исключение, выполняется до обращения к rng.
2. Один вызов `rng.next()` → `r ∈ [0, 1)`: `r < 0.5` → `heads`, иначе `tails` ([[decisions/coin#D-002]]). Ребра нет ([[decisions/coin#D-004]]).
3. `win = outcome === side`.
4. `payout = win ? bet × PAYOUT_MULTIPLIER : 0`, где `PAYOUT_MULTIPLIER = 1.96` (честные 2 минус 2 % house edge, [[decisions/coin#D-001]]). Модуль возвращает сырое произведение, до центов его округляет платформа: 3.33 → 6.5268 → 6.53.

`Math.random` не используется. Исход полностью задаётся переданным `rng`, поэтому в тестах им управляют через `fixedRng`.

## Интерфейс
- Корень `data-testid="game"` с `data-state`:
  - `idle` — до первого броска и после ошибки ([[decisions/coin#D-014]]);
  - `playing` — пока запрос `startRound` в пути: кнопки заблокированы, монета вращается;
  - `won` / `lost` — по `view.win`.
- Остальные элементы ([[decisions/coin#D-007]]):
  - `balance` — баланс;
  - `bet-input` — ставка, по умолчанию 1, `min`/`max` берутся из `limits` ответа `open()`;
  - `side-heads` / `side-tails` — выбор стороны, выбранная кнопка помечена `aria-pressed="true"`, по умолчанию орёл;
  - `play` — бросок;
  - `outcome` — «Орёл» или «Решка»;
  - `payout` — выплата;
  - `error` — ошибка платформы в виде «КОД: текст».
- Суммы показываются через `toFixed(2)` ([[decisions/coin#D-015]]). Ставка уходит как `Number(value)` без проверки на клиенте: лимиты проверяет платформа (`BET_OUT_OF_LIMITS`).
- При загрузке вызывается `open()`. Если платформа вернёт `activeRound`, страница его покажет. Для «Монетки» этого не бывает, но так интерфейс устойчив к обновлению страницы.
- Известные мелочи из ревью: если в успешном ответе нет `view.outcome`, `data-state` остаётся `playing` (R-1). Пустое поле ставки отправляется как 0 и получает `BET_OUT_OF_LIMITS` (R-2).
